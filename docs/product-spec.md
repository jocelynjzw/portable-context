# portable-context 产品规格与验收

> 长期个人记忆和共享任务上下文都是核心需求。现有实现提供通用记忆条目，任务上下文的专用能力仍待开发和验收。

| 日期 | 变更 |
| --- | --- |
| 2026-11-23 | 建档，记录两项核心需求、实现差距和验收条件。 |

## 用户与范围

面向日常同时用多个 AI 工作的人。例如，用一个 AI 起草虚构社区地图的发布通知，用另一个 AI 写代码。两边都需要项目面向谁、这次发布的目标和材料、已定事项，以及做到哪一步。共用这些信息可以减少重复说明和来回复制。跨工具、跨设备服务于这套日常工作。

| 范围 | 要求 |
| --- | --- |
| 范围内 | 持续维护长期个人记忆，按任务分享和读取当前上下文，保留出处与版本。在首版云端范围内验收用户自己的 Notion 专用库。 |
| 范围外 | 一次性迁移、仅为 Codex 新会话保存偏好、要求不同模型答案一致、统一入口、监听全部聊天、自动派工或交接进度。远程 HTTP MCP（含认证）和手机接入不纳入下列最小实现。 |

## 共享规则

| 项目 | 需求 |
| --- | --- |
| 长期记忆 | 保存跨任务可复用的个人背景、偏好或长期项目背景。开始新任务时，只选本次相关且允许共享的条目。 |
| 任务上下文 | 保存这次工作的目标、约束和范围、材料及出处、讨论结论和决定、进展及下一步。它与长期记忆互补。 |
| 来源与版本 | 关键结论可回查到材料或讨论的原始位置，并能看出来源时间。更新后默认返回当前决定，旧决定留作可明确查看的历史。同一决定存在冲突时，提示核对。 |
| 范围与隔离 | 默认只返回用户选定且允许共享的任务内容。任务标识只用来定位任务，读写仍须校验权限。未选中的长期记忆、未共享材料和其他任务的内容不得通过列表、搜索、直接读取或引用意外暴露。引用不得扩大原材料的访问权限。 |
| 发现与选择 | 首版由用户在当前会话明确提供任务标识。用户不知道标识时，可主动要求查找，客户端只列出有权访问的候选，由用户确认。缺少标识、匹配不唯一或无权访问时，不猜、不加载任务内容。客户端须主动调用，切换会话后重新选择。 |

## 当前实现与差距

| 项目 | 当前行为与缺口 |
| --- | --- |
| 内容和来源 | `memory_write` 接收 `subject`、`content`、`source`、`time`、`scope`。可以用主体标记虚构项目，把目标、约束、决定、进展或材料位置手工写入内容，填写来源和日期。来源是文本，目前没有专门的材料引用关系，也不会校验引用是否可访问。 [字段定义](../src/store.ts) |
| 任务聚合 | `memory_search` 可按关键词搜索，并筛选 `subject` 和 `scope`。`scope` 是文字筛选条件，不提供权限隔离。手工给多条记忆填同一范围，仍缺少独立任务标识、任务成员关系和按任务聚合。 [搜索实现](../src/store.ts) |
| 当前快照 | `id` 标识单个版本，`rootId` 串起同一条记忆的版本，`version`、`status` 和替代关系区分新旧。`memory_correct` 检查当前 `id` 和 `expectedVersion`，搜索只返回有效版本。`memory_read` 可按 ID 查某个版本。这些能力只覆盖单条记忆，目前没有任务级的当前快照。 [存储实现](../src/store.ts) · [Notion 实现](../src/notion.ts) |
| 专用接口与使用规则 | MCP 仅注册 `memory_write`、`memory_search`、`memory_read`、`memory_correct`、`memory_delete`。命令行只有通用记忆的 `list`、`show`、`search`、`correct`、`delete`、`export`。目前没有专用任务接口，也没有任务发现、确认、共享选择和权限规则。 [MCP 工具](../src/server.ts) · [命令行](../src/cli.ts) |
| 验证范围 | 稳定版只验收了官方 Codex CLI 在本机的跨会话使用。仓库测试还覆盖两个独立本机测试客户端共用 SQLite 和版本纠正。未发布的 Notion 存储只做过离线模拟测试。 [本机测试](../test/integration.test.mjs) · [Notion 测试](../test/notion.test.mjs) · [发布记录](../CHANGELOG.md) |

**能存任意文本 ≠ 任务上下文产品已完整。**

## 最小实现计划（尚未实现）

1. 本机先跑通任务闭环。定义任务标识、写入和读取方式、材料引用、当前快照及版本冲突处理。支持明确选择要共享的信息，并执行任务间隔离和访问检查。
2. 用独立会话验收本机闭环，再用另一种已配置的独立客户端验证多 AI 用法。分别记录通过的客户端和场景。
3. 用独立 Notion 测试库验收真实接口与两台设备。每台电脑各自启动本机 MCP 服务。通过后再更新公开支持范围。

## 验收标准（待执行）

以下均使用虚构的社区地图项目。`task-A` 和 `task-B` 是示例任务标识，具体接口随实现确定。

| 操作 | 通过条件 |
| --- | --- |
| 1. 写入 `task-A`，保存发布目标、无障碍约束、地图草稿及出处、先做列表页的决定，并记录进展和下一步。选一条长期记忆共享。 | 当前任务能逐项取回这些信息，且能区分长期背景和本次任务内容。 |
| 2. 在有权限的独立客户端或新会话，只给出 `task-A` 标识并主动读取。 | 无需复制材料、记忆 ID 或聊天记录，即可取回第一步的当前内容。未选择任务时不会自动加载。 |
| 3. 把决定改为先做地图页，重新读取。 | 当前结果只把「先做地图页」标为有效。显式查历史时能看到旧决定及其原出处。 |
| 4. 建立 `task-B`，写入主题相似但决定不同的内容，再读取 `task-A`。 | `task-A` 的快照和搜索结果里没有 `task-B` 的条目。 |
| 5. 核对地图草稿和更新后的决定。 | 结果能指出各自的来源、来源时间及原材料或讨论的可核对位置。 |
| 6. 添加未共享材料和未选中的长期记忆。分别用有任务权限和无任务权限的客户端检查。 | 有任务权限的客户端只读到已共享条目。无任务权限的客户端即使知道标识，也不能通过列表、搜索、直接读取或引用获得任务内容。 |
| 7. 在独立 Notion 测试库中从设备一写入，设备二主动读取并更新，再由设备一重新读取。 | 真实 Notion API 和跨设备读写都通过。能核对当前决定、来源和隔离结果。离线模拟测试不能替代这一步。 |
